首装传输实际使用 **Mac 上运行的生产 Java `NativeOtaClient`，经安卓 USB 中继和仪表热点**。Android APK 0.2.2 另已安装到 OnePlus 8。协议核心与实机接收器已联通，不等于 APK 所有界面流程均已逐项验收。真实传输中出现过等待接收方关闭连接超时；最终以 SSH 认证和 `COMMITTED` 确认成功。

**没有宣称 NATIVE 0.1.4 已实机首装。** 仓库可将新构建组件封装为新 NATIVE 候选，但新的密钥、二进制或包装产物仍需对应验收。已提交组件 4 的仪表不应再使用组件 3 首装包。

## 关键修复

- 安装器通过固定系统 PATH 查找 `setsid`，兼容实机 `/usr/bin/setsid` 布局。
- 允许受信任 root 组的目录布局，同时检查非 root 组成员、符号链接及其他用户可写路径。
- 首装三个入口统一使用终止型 wrapper，避免脚本返回后继续原厂 MCU 更新流程。
- Android 发送安装确认前保存不确定状态，之后等待接收方关闭连接；超时不自动重发，也不报告已安装。
- Dropbear 启用密码认证，配合实机 BusyBox 1.29.3 的 SHA-512 crypt；原 ramdisk 测试夹具 BusyBox 为 1.22.1，两者不混作证据。

## 持久化范围

组件新增 `/opt/703t-ssh/releases/`、`hostkeys/`、`transactions/`、`component-state` 以及 `/etc/init.d/S97ssh703t`。实机单独设置密码还修改了 `/etc/shadow`，并收紧其备份权限。

安装、密码更新、正常重启前后，Launcher 与 rcS 字节哈希不变。补丁不包含 boot、kernel、MCU、Launcher、DVR 或整机 rootfs 载荷。原厂 OTA 连接仍会停止 DVR/部分投屏进程并操作暂存目录，不能把「未替换业务文件」理解为升级过程无运行影响。

回退覆盖 SSH 组件的启动入口和提交状态，保留主机身份、旧版本及诊断记录。系统密码、其他自制软件、整机分区和 MCU 不在该快照内。

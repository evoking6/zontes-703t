# 测试说明

## 主机离线回归

从仓库根目录执行，JDK 17 设置为 JAVA_HOME（macOS 无变量时使用脚本中的默认路径）：

```sh
python3 android/testing/test_native_ota.py
python3 -m unittest discover -s android/testing -p test_release_key.py -v
python3 tools/testing/test_ssh_bootstrap.py
```

TCP 测试仅监听 loopback，直接编译并调用生产 Java 核心；覆盖签名、清单、路径、基线、拆包/粘包、传输确认、失败断开和取消等。固件发布身份测试使用临时目录；封装器测试用临时密钥与合成载荷，不访问设备。

原厂全量包不在仓库，未提供时仅跳过对应的一个固定哈希测试。可通过 `SSH703T_FACTORY_ARCHIVE` 指向自己的精确原厂包，或放在仓库根目录，以运行全部 34 项。其余测试不依赖原厂包。

源码语法及 Android 构建：

```sh
python3 -m compileall -q tools android firmware/testing
for script in tools/ssh703t/*.sh tools/ssh703t/S97ssh703t; do sh -n "$script" || exit; done
python3 android/build_apk.py
```

`InstrumentWifiCodeChecks.java` 另外提供标准 Wi-Fi/Carbit 参数、四种二维码旋转和非法输入检查。编译时使用 Android SDK android.jar、ZXing JAR，以及 InstrumentWifiCode、InstrumentQRScanner；运行时仅调用其纯解码路径，不访问真实热点。

已构建 APK 后可运行（platform 路径按本机 SDK 调整）：

```sh
QR_TEST_CP="android/build/release/classes:android/libs/zxing-core-3.5.4.jar:$ANDROID_SDK_ROOT/platforms/android-37.0/android.jar"
"$JAVA_HOME/bin/javac" -encoding UTF-8 --release 8 -cp "$QR_TEST_CP" -d android/testing/generated/qr android/testing/InstrumentWifiCodeChecks.java
"$JAVA_HOME/bin/java" -cp "android/testing/generated/qr:$QR_TEST_CP" cn.local.instrument703t.InstrumentWifiCodeChecks
```

## 隔离 ARM64 环境

`firmware/testing/` 的脚本固定访问 **`emulator-5556`**，先检查 `ro.kernel.qemu=1`、root、AArch64。不要把序列号改为真实安卓或仪表，也不要在 `python -O` 下运行（测试前提使用 assert）。测试会修改专属 chroot、临时降低模拟器 SELinux 并执行模拟器重启；仅适合专用可丢弃实例。

需要自行准备的未分发夹具：

```text
analysis/ramdisk/GT/bin/busybox
analysis/ramdisk/GT/lib/*
analysis/original/Launcher
analysis/original/etc/init.d/rcS
```

源码保持原验证目录布局。BusyBox 与动态库必须匹配；密码验收需要与实机一致且支持 SHA-512 crypt 的 passwd 实现，可用 `SSH703T_TEST_PASSWD_BINARY` 指定 chroot 内路径。密码脚本依赖 pexpect，密码由运行时随机生成，不使用个人设备密码。

流程与用途：

1. 专属 ARM64 Android 模拟器 root 后，`prepare_chroot.py` 创建 `/data/local/tmp/703t-ssh-root`；若已存在则拒绝覆盖。
2. 将 `SSH703T_TEST_BUNDLE` 设为本次要验证的包的绝对路径；NATIVE wrapper 测试必须用 NATIVE 包。未设置时事务脚本默认历史 NATIVE 0.1.3，密码专项默认组件 0.1.4。
3. `check_incremental_rollback.py`：正常安装、重入、升级、失败和超时回退，校验原文件不变和旧服务恢复。
4. `check_ota_bootstrap.py`：三种入口生命周期，检查父流程不恢复及重放入口清理。
5. `check_bootstrap_reboot.py`：真实重启该模拟器，核对新 boot ID、服务重建、主机身份和原文件不变。依赖前面的事务测试准备好的状态。
6. `check_password_auth.py`：随机密码、公钥、错误密码、非 root 拒绝及服务重启后的身份保留。

这些测试把 AP 绑定替换为 `127.0.0.1:2222`、注入面板和失败场景；测试包无发布签名，留在 testing/generated。它们证明隔离条件下的事务行为，不能直接证明车辆异常断电恢复。

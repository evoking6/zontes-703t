# 构建与使用

以下命令均从仓库根目录运行。构建不会自动连接或刷写仪表。只有 [实机记录](实机验证记录.md) 对应的基线获得了本轮验收。

## 环境

- Python 3.11+、OpenSSL、OpenSSH 的 `ssh-keygen`。
- SSH 静态编译：`aarch64-linux-musl-gcc` 工具链及相同前缀的 ar、ranlib、strip、readelf，另需 make 和主机编译工具。编译器放在 PATH。
- Android：JDK 17、Android SDK platform 37（或 `android-37.0`）、build-tools 36.0.0。
- 自行合法取得精确基线原厂包，放到仓库根目录，文件名 `JC_703T25_V02.26.02.02.60.tar`。原厂包不会入 Git，构建器校验固定 SHA-256。

## 三类密钥

| 身份 | 本地位置 | 用途 |
| --- | --- | --- |
| 固件发布 RSA 私钥 | `android/.firmware-signing/release-private.pem` | 签名自制 TAR；对应公钥嵌入 APK，上传前验签 |
| SSH 所有者 Ed25519 私钥 | `firmware/.ssh-access/id_ed25519` | 登录自己的仪表；仅公钥进入 SSH 载荷 |
| APK 签名身份 | `android/.signing/` | Android 安装和后续覆盖升级身份 |

这些目录均自动生成并被 Git 忽略。丢失身份后，旧 APK 不会自动信任新固件签名；改变 APK 签名也不能直接覆盖旧安装。不要将个人生成的 SSH 包当作公共通用包，因为它包含对个人私钥的授权。

设备另在首次启动时生成自身 SSH 主机密钥，保存在 `/opt/703t-ssh/hostkeys/`，不由所有者登录私钥替代。固件包不设置默认密码。

## 构建 Android

```sh
python3 android/build_apk.py --sdk "$ANDROID_SDK_ROOT" --java-home "$JAVA_HOME"
```

首次构建自动生成发布密钥并嵌入公钥。APK 位于 `dist/703T-OTA-0.2.2.apk`，包签名和哈希报告也在 dist。SDK/JDK 也可通过环境变量指定；macOS 默认路径写在脚本中。ZXing 依赖随源码保留并校验哈希。

Android 10+ 可从相机或相册识别仪表投屏二维码，再按系统授权连接热点；解析在本地完成，不访问二维码中的下载网址。APK 支持已知原厂全量 TAR 和用相同发布身份签名的全量/文件增量 TAR。

不要把查询 OTA 端口当作无副作用健康检查：原厂 Launcher 建立 8081 连接就可能停止 DVR 和部分投屏进程。

## 构建 SSH 组件 0.1.4

```sh
python3 tools/build_ssh_firmware.py
```

构建器校验原厂基线、下载并校验固定版本 Dropbear、静态交叉编译、生成独立 SSH 登录密钥、填充安装器基线、自检及回退脚本，然后签名。

输出 `dist/JC_703T25_SSH_0.1.4_CANDIDATE.tar`，附带 `.sha256`、`.sig` 和构建记录。**这是已有可信 SSH 下使用的组件包，不能直接作为原厂 OTA 首装包。** 它的普通入口会返回，缺少用于隔离原厂后续流程的终止型 wrapper 和 Android 所需的内部签名 manifest。

release `ssh-20261115-4`、counter 4 是既有组件身份。修改设备端载荷并发布新版本时，应一并提升 builder 中 RELEASE、COUNTER 与输出版本，不要重复使用相同 release 发布不同内容。安装器会拒绝同版本目录内容不一致和组件降级。

## 封装新的 NATIVE 候选

公共仓库不包含个人历史组件 0.1.2。以下将自己构建的 0.1.4 封装为新的候选，**没有继承历史 NATIVE 0.1.3 的实机首装结论**：

```sh
python3 - <<'PY'
import hashlib
from pathlib import Path
import sys
sys.path.insert(0, 'tools')
from build_ssh_bootstrap import build
source = Path('dist/JC_703T25_SSH_0.1.4_CANDIDATE.tar')
result = build(
    source, hashlib.sha256(source.read_bytes()).hexdigest(),
    Path('dist/JC_703T25_SSH_NATIVE_0.1.4_CANDIDATE.tar'),
    'ssh-local-bootstrap4',
    Path('android/assets/release-public.pem'),
    Path('android/.firmware-signing/release-private.pem'))
print(result)
PY
```

输入应是刚刚完成审阅的本地构建物；对外部输入应使用独立取得的预期哈希，不能仅自算哈希代替来源核验。封装器还验证组件的 detached signature，仅允许 SSH 组件路径，替换三个入口，加入签名 manifest。输出必须不存在，避免覆盖已记录的产物。

`tools/build_ssh_bootstrap.py --help` 提供相同参数。无参数模式保留历史 0.1.3 复现入口，仅适用于持有精确旧组件和原签名身份的维护者；该历史输入不随仓库分发。新输入必须使用不同输出名和 release。

不要对组件直接调用通用 `native_ota.py` 就用于首装：通用签名器不会替你补齐终止型 wrapper 或安装事务。

## 安装后的 SSH 验收

先让仪表完成首装重启，重新接入仪表热点。首次核验并记录本机主机指纹；之后启用严格主机校验，不能把变化的主机身份自动接受为同一设备。

```sh
ssh -i firmware/.ssh-access/id_ed25519 -o IdentitiesOnly=yes root@192.168.3.1
```

登录后只读检查：

```sh
cat /proc/lcdv
uname -a
cat /opt/703t-ssh/component-state
cat /opt/703t-ssh/transactions/*/result.json
test ! -e /opt/703t-ssh/pending
/etc/init.d/S97ssh703t status
sha256sum /usr/bin/Launcher /etc/init.d/rcS
```

应核对当前 release 对应的最近事务 `COMMITTED`、自检通过、无 pending、监听地址正确；历史失败事务可以保留，不能把任意一个旧 COMMITTED 当成当前成功。再从已提交 release 目录执行 `post-install-test.sh`，它只验证 SSH 组件契约，不代表全部车辆功能验收。

需要系统密码认证时，在已经核验身份的 SSH 会话内自行运行 `passwd`，检查 `/etc/shadow` 和存在的 `/etc/shadow-` 权限为 0600，再验证正确密码、公钥和一次错误密码拒绝。密码不应出现在命令参数、包、脚本或文档里。

后续通过可信 SSH 安装组件时，先在电脑验 detached signature 与哈希，再上传到独立暂存目录并比对远端哈希，解包并执行 `ssh703t/install.sh`，核对新事务。不要执行包内 `updateFile*.sh` 作为 SSH 维护入口；这些路径属于原厂安装布局。组件安装器自身不自动重启，重启验收是单独操作。

Dropbear 此配置不提供 SFTP/端口转发。上传自制文件可通过已认证 SSH 的标准输入写入暂存文件，校验 SHA-256 后再执行；现代 scp 默认 SFTP 不能直接假设可用。

## 停用及回退

在已确认的 release 目录运行 `disable.sh` 可停用本组件的自启动/服务。安装失败优先由安装事务自动回退；人工执行 `rollback.sh` 需要指定真实事务目录并核对记录。脚本保留旧版本和主机身份，不做整机恢复，也不回滚单独设置的系统密码。
